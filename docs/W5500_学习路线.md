# W5500 学习路线（STM32 + ioLibrary 实战版）

面向目标：你已经把 W5500 跑通了（能读 `VERSIONR=0x04`、`PHYLINK=1`、PC 能 `ping 192.168.227.88`）。接下来学习路线应该以“能做项目”为导向：从寄存器/链路验证 → Socket API → 常用协议（TCP/UDP/DNS/DHCP/SNTP/HTTP）→ 可靠性与性能 → 工程化。

本路线按阶段推进，每一阶段都给出“你需要掌握什么 + 建议动手做什么 + 验收标准 + 常见坑”。

## 0. 你当前的起点（已完成）

你现在已经具备：

- SPI 通信正常：`VERSIONR=0x04`
- 物理链路正常：`PHYLINK=1`
- 网络参数正确：IP/SN/GW/DNS 写入成功
- L2/L3 基本可达：PC 能 ping 到板子 IP

这些信息在你的串口打印里已经体现（`w5500_dump()`），这是非常标准的 bring-up 流程。

## 1. 第一阶段：芯片与寄存器“看懂 + 能验证”

### 1.1 目标

- 看懂 W5500 的基本结构：Common 寄存器、Socket 寄存器、TX/RX Buffer
- 理解 ioLibrary 在做什么：回调注册、SPI 事务、寄存器读写封装

### 1.2 需要掌握的知识点

- SPI 帧格式（W5500 VDM/FDM 模式差异，控制字节含义）
- `MR`（Mode Register）和几个关键位（如 Ping Block）
- `PHYCFGR`（链路、速率、单双工的状态）
- `GAR/SUBR/SIPR/SHAR`（网关/掩码/IP/MAC）
- Socket 栈结构：每个 Socket 都有自己的模式、端口、状态机、TX/RX 指针

### 1.3 动手任务

- 任务 A：写一个“寄存器读写自检”
  - 读 `VERSIONR`、`MR`、`PHYCFGR`、`SIPR/SUBR/GAR/SHAR`
- 任务 B：抓逻辑分析仪波形
  - 观察一次完整 `WIZCHIP_READ()` 的 SPI 时序：CS 下降 → 地址/控制字节 → 读数据 → CS 上升

### 1.4 验收标准

- 你能解释：为什么 `VERSIONR` 读不到通常是 SPI/CS/时序问题
- 你能解释：为什么 `ARP 有但 ping 不通` 多数是 Ping Block 或回包路径

### 1.5 常见坑

- PC 在错误网卡发 ARP（Wi-Fi/以太网同时存在时）
- 路由器开了无线隔离导致 Wi-Fi 访问不到有线端设备
- MAC 冲突（同网段两台设备 MAC 一样会出现“时通时不通”）

## 2. 第二阶段：Socket API 入门（TCP/UDP 能收能发）

### 2.1 目标

- 只用 W5500 的 `socket.c/socket.h` API，不写协议栈，完成 TCP/UDP 通信

### 2.2 推荐顺序

- UDP Echo（最简单）→ TCP Server → TCP Client

### 2.3 动手任务（强烈推荐）

#### 任务 A：UDP Echo（板子 UDP 5000）

- 板子：打开 UDP Socket，绑定端口 5000；收到什么回什么
- PC：用网络调试助手/自写脚本发 UDP 包，验证回显

验收：

- 能持续发送/接收 1 分钟不掉线
- 能处理不同长度（1\~1400 字节）的 UDP 数据

#### 任务 B：TCP Server（板子监听 5001）

- 板子：`listen()` → `accept`（状态变化）→ `recv()` → `send()`
- PC：用 `telnet`/`nc`/网络调试助手连入，发字符串看回显

验收：

- 连接建立、断开、重连流程稳定
- 断网/拔线后能恢复（需要状态机处理）

#### 任务 C：TCP Client（板子主动连 PC）

- PC：开一个 TCP server（Python/网络调试助手）
- 板子：定时连上 → 发心跳 → 断开重连

验收：

- PC 重启 server 后，板子能自动重连

### 2.4 需要掌握的核心概念

- Socket 状态机：`SOCK_INIT/SOCK_LISTEN/SOCK_ESTABLISHED/SOCK_CLOSE_WAIT/...`
- 发送前检查 TX free size，接收检查 RX size
- MTU 与分包：一次 send/recv 不一定等于一次应用层消息

## 3. 第三阶段：常用网络服务（按项目需求挑）

这一阶段不必全学，按你要做的项目选。

### 3.1 DHCP（自动获取 IP）

适用：设备要插到不同路由器环境，不方便固定 IP。

你要理解：

- DHCP 的租约、续租
- DHCP 拿到 IP 后要写回 W5500（ioLibrary 已封装）

验收：

- 插不同路由器都能自动拿到 IP，串口打印显示新 IP

### 3.2 DNS（域名解析）

适用：你要访问公网服务器或局域网域名。

验收：

- 能解析 `pool.ntp.org` 或你自定义域名并连接成功

### 3.3 SNTP（对时）

适用：日志时间戳、加密协议、定时任务。

验收：

- 上电后获取 UTC 时间并周期性校时

### 3.4 HTTP（轻量 Web 配置页）

适用：设备配网、参数配置、状态页面。

验收：

- PC 浏览器能打开板子页面
- 能修改参数并保存（EEPROM/Flash）

## 4. 第四阶段：工程化与可靠性（从“能跑”到“能用”）

### 4.1 断网/插拔网线恢复

- 检测 PHY link 变化（周期读 `PHYCFGR` 或用 `CW_GET_PHYLINK`）
- Link Down：关闭 socket，清状态
- Link Up：重新初始化网络/重建连接（按业务需求）

验收：

- 拔线 10 秒再插回，1 分钟内自动恢复通信

### 4.2 超时、重试与异常处理

- 设置 socket 超时/重试参数（ioLibrary 支持）
- 处理 `SOCK_CLOSE_WAIT`、`SOCK_CLOSED` 等边界状态

验收：

- 对端异常断电，板子不会卡死在某个状态

### 4.3 性能（吞吐与延迟）

- 把 SPI 改为 burst 读写（可选）
- 调整 SPI 分频、Socket 缓冲区分配
- 避免在中断里做长时间网络操作（保持“中断抓事件 + 主循环状态机”）

验收：

- 达到目标吞吐（例如 UDP 500KB/s 或 TCP 200KB/s，按你的 SPI 时钟与 MCU 频率决定）

## 5. 第五阶段：把 W5500 当成“项目模块”使用

建议形成固定架构：

- `w5500_init()`：一次性初始化（回调注册 + chip init + netinfo）
- `w5500_link_task()`：周期检测 link，处理重连
- `net_app_task()`：应用层 TCP/UDP 状态机（例如你的 RS485\_Task 那种风格）
- 串口日志策略：调试期输出 HEX/关键状态，稳定后输出统一格式 `RX:`/`TX:`

验收：

- 网络层与业务层解耦，后续换协议/换端口不影响底层

## 6. 推荐资料（选你容易看懂的）

- WIZnet W5500 Datasheet（重点看：SPI 访问方式、Common 寄存器、Socket 寄存器、Buffer 操作）
- WIZnet ioLibrary GitHub（看 socket API 的典型用法）
- 抓包工具：Wireshark（ARP/DHCP/DNS/TCP 重传都靠它最快定位）
- 逻辑分析仪：Saleae（SPI 时序/CS 翻转/突发读写一眼看穿）

## 7. 你下一步最建议做的 3 个小实验（最有学习价值）

1）UDP Echo（板子 5000）\
2）TCP Server（板子 5001，PC 连入发字符串回显）\
3）拔网线/插回恢复（link down/up 自动重建 socket）
