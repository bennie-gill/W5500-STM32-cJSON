# W5500 第一阶段 Step 5：PC 侧验证（ARP / 邻居表 / 抓包 / 走错网卡）

目标：你能在 PC 上用最少命令，把“为什么不通”归类到正确层级，并快速定位：
- 是不是走错网卡
- 是不是 ARP 没通
- 是不是 ping 被屏蔽
- 是不是路由器隔离

## 1. 两条原则（非常重要）

- 原则 1：先看 ARP，再谈 ping  
  ARP 不通时，ICMP 怎么调都没用。
- 原则 2：多网卡时，ping 可能走错接口  
  用 `ping -S <源IP>` 强制指定源地址最快。

## 2. 先确认自己在同网段（ipconfig）

```powershell
ipconfig
```

你要看两点：
- 你想走的那张网卡（以太网/无线）是不是 `192.168.227.x/24`
- 默认网关是不是 `192.168.227.162`

典型坑：
- 以太网拿到 `169.254.x.x`：说明 DHCP 没拿到地址（APIPA），它不属于 192.168.227.0/24
- WLAN 是 192.168.227.x，但你实际物理是直连以太网：此时 ARP 会发错地方

## 3. 用 ARP/邻居表决定“走哪条排查分支”

### 3.1 先触发一次访问

```powershell
ping 192.168.227.88 -n 1
```

### 3.2 看 ARP 表（传统方式）

```powershell
arp -a | findstr 192.168.227.88
```

有输出且是一个真实 MAC：说明 ARP 通了。  
无输出：说明 ARP 还没学到（可能对端没回、也可能走错网卡）。

### 3.3 看邻居表（更直观）

```powershell
powershell -NoProfile -Command "Get-NetNeighbor -AddressFamily IPv4 | ? IPAddress -eq '192.168.227.88' | fl IPAddress,InterfaceAlias,State,LinkLayerAddress"
```

常见判读：
- `State = Reachable` 且 `LinkLayerAddress != 00-00-00-00-00-00`：ARP OK
- `State = Unreachable` 且 `LinkLayerAddress = 00-00-00-00-00-00`：ARP 失败

## 4. 强制指定源地址（避免走错网卡）

先确认你以太网的 IPv4，例如 `192.168.227.10`，然后：

```powershell
ping -S 192.168.227.10 192.168.227.88
```

这个命令的意义：
- 不让 Windows 自己选路由，而是强制从你指定的接口发包

## 5. Wireshark 抓包：3 分钟定位 90% 的问题

### 5.1 抓什么

过滤器：
- `arp`：看 ARP Request/Reply 是否成对出现
- `icmp`：看 Echo Request/Reply 是否成对出现

### 5.2 判读模板

- 只看到 PC 发 ARP Request，看不到 Reply：  
  对端没回 ARP（可能对端没在线/不在同二层/走错网卡/隔离）
- ARP Reply 有了，但 ICMP Reply 没有：  
  多数是 PingBlock 或对端不响应 ICMP（W5500 可通过 MR.PB 控制）

## 6. 路由器隔离（Wi-Fi 能上网但访问不到有线设备）

如果你是：
- PC 走 Wi-Fi
- W5500 接路由器 LAN（有线）

但互相访问不到，常见原因是路由器开启了：
- 无线客户端隔离 / AP 隔离 / Guest 网络隔离

验证最快方法：
- 让 PC 也用网线接到同一个路由器 LAN，再 ping W5500  
  - 有线能通、Wi-Fi 不能通：就是隔离/VLAN 造成的

## 7. Step 5 的验收（你做完要得到什么）

- `ping 192.168.227.88` 0% 丢包
- `arp -a` 或 `Get-NetNeighbor` 能看到真实 MAC
- Wireshark 中能看到 ARP/ICMP Request 与 Reply 成对出现

完成后进入 Step 6（逻辑分析仪对齐 SPI 波形）。
