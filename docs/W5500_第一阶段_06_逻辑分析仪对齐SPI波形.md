# W5500 第一阶段 Step 6：逻辑分析仪对齐 SPI 波形（把“读寄存器”变成看得见）

目标：你能做到：
- 用逻辑分析仪抓到一次 `getVERSIONR()` 的 SPI 波形
- 在 MOSI 上识别出寄存器地址与读写控制字节
- 在 MISO 上看到返回数据 `0x04`

一旦你能把“软件动作”和“SPI 波形”对齐，后面任何异常都能用波形定位，不靠猜。

## 1. 连接与软件设置（Saleae 为例）

### 1.1 连接 4 根线

- CS（片选）
- SCK（时钟）
- MOSI
- MISO

建议再额外接一根 GND（逻辑分析仪地与板子地共地）。

### 1.2 采样率建议

- 至少 10MHz（更高更好）
- 如果你后续提高 SPI 时钟，采样率至少是 SPI 时钟的 4~10 倍

### 1.3 触发建议

- 触发：CS 下降沿
- 采样窗口：触发后 1~2ms 足够覆盖一次读写

## 2. 你要抓的“目标事务”是什么

以读 `VERSIONR` 为例：
- `VERSIONR` 寄存器地址 = `0x0039`  
  [w5500.h](file:///i:/AI/w5500/BSP/w5500.h#L405-L407)

在本工程的 W5500 驱动实现里，读寄存器会发送 3 个字节头：
- Addr High
- Addr Low
- Control（包含 R/W 与 block 选择）

实现位置：
- [w5500.c](file:///i:/AI/w5500/BSP/w5500.c#L65-L89)

## 3. 读 Common 寄存器时 MOSI 应该是什么

Common Register Block 的 block 值是 0：
- `WIZCHIP_CREG_BLOCK = 0x00`  
  [w5500.h](file:///i:/AI/w5500/BSP/w5500.h#L67-L67)

读操作控制位：
- `_W5500_SPI_READ_ = (0x00 << 2)`  
  [w5500.h](file:///i:/AI/w5500/BSP/w5500.h#L64-L65)

因此读 `VERSIONR(0x0039)` 的 MOSI 头 3 字节应为：
- `00 39 00`

随后 MISO 会返回一个字节：
- `04`

同理读 `PHYCFGR(0x002E)`：
- MOSI：`00 2E 00`
- MISO：返回一个 PHY 配置字节（bit0=Link，bit1=Speed，bit2=Duplex）
  - 位定义参考：[w5500.h](file:///i:/AI/w5500/BSP/w5500.h#L766-L781)

## 4. 如何在代码里“制造一次可重复的读事务”

你已经有 `w5500_dump()`，里面会读 `VERSIONR`、`MR`、`PHYLINK` 等寄存器并打印：
- [bsp_w5500.c](file:///i:/AI/w5500/BSP/bsp_w5500.c#L60-L77)

所以最简单的抓法：
- 上电/复位，让 `w5500_dump()` 运行一次
- 在串口看到打印的同时，逻辑分析仪一定能抓到对应 SPI 事务

如果你想抓“重复波形”更方便对齐：
- 临时把 `w5500_dump()` 放进一个 500ms 的循环里（抓完再改回只打印一次）

## 5. 你应该如何判读波形（从外到内）

- Step 1：先看 CS 是否有清晰的低电平窗口（一次事务一个窗口）
- Step 2：在 CS 低电平窗口内看 SCK 是否有连续时钟
- Step 3：用 SPI 解码器（Mode0、MSB First）解码 MOSI/MISO
- Step 4：在 MOSI 找 `00 39 00`，对应 `VERSIONR`
- Step 5：确认 MISO 紧跟返回 `04`

## 6. 常见异常波形与结论（快速对照）

- MOSI 有 `00 39 00`，但 MISO 一直 0xFF 或 0x00：
  - 多数是 MISO 线没接好/短路/悬空/电平不匹配
- MOSI 的第三字节不是 0x00：
  - block 或 R/W 位不对（驱动配置/宏/IO 模式可能不一致）
- CS 在事务中间抖动（被拉高又拉低）：
  - CS 控制或临界区存在问题（中断打断/多线程访问）

## 7. Step 6 的验收（你做完要得到什么）

- 能在 MOSI 上指出 `00 39 00` 是 `VERSIONR` 读事务
- 能在 MISO 上看到返回 `0x04`
- 能用同样方法定位 `PHYCFGR/MR/SIPR` 等寄存器读写
