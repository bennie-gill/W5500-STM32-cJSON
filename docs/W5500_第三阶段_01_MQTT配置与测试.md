# W5500 第三阶段：MQTT 通信配置与 MQTTX 测试指南

本指南详细介绍了如何在 W5500 上从零开始实现 MQTT 协议，并通过 MQTTX 客户端进行信息发送与数据回传（Echo）测试。

---

## 1. 准备工作

### 1.1 软件准备
- **MQTTX 客户端**：用于模拟云端/上位机进行消息订阅与发布。[下载地址](https://mqttx.app/)
- **公共 MQTT Broker**：测试建议使用公共服务器，如 `broker.emqx.io` (IP: 116.62.226.174, Port: 1883)。
- **STM32 工程**：基于之前完成的 W5500 静态 IP 配置工程。

### 1.2 库文件确认
确保工程中包含 `ioLibrary_Driver/Internet/MQTT` 目录下的以下文件：
- `MQTTClient.c/h`：Paho MQTT 核心逻辑。
- `mqtt_interface.c/h`：W5500 与 Paho MQTT 的接口层。
- `MQTTPacket/src`：MQTT 报文封装库。

---

## 2. 步骤一：接口层移植 (mqtt_interface.c)

WIZnet 提供的默认接口层需要针对 STM32 进行微调，特别是**定时器**和**非阻塞读写**。

### 2.1 定时器心跳 (MilliTimer)
MQTT 需要一个 1ms 的心跳来处理超时和 Keep-alive。
在 `Core/Src/stm32f1xx_it.c` 的 `SysTick_Handler` 中添加：

```c
/* stm32f1xx_it.c */
extern void MilliTimer_Handler(void);

void SysTick_Handler(void) {
    HAL_IncTick();
    MilliTimer_Handler(); // MQTT 1ms 心跳
}
```

### 2.2 修复读写函数超时逻辑
修改 `mqtt_interface.c` 中的 `w5x00_read`，使其支持超时等待，否则在高并发下容易掉线。

```c
/* mqtt_interface.c */
int w5x00_read(Network* n, unsigned char* buffer, int len, int timeout) {
    uint32_t start_tick = HAL_GetTick();
    int recv_len = 0;
    while (recv_len < len) {
        int ret = recv(n->my_socket, buffer + recv_len, len - recv_len);
        if (ret > 0) {
            recv_len += ret;
        } else if (ret != SOCK_BUSY && ret < 0) {
            return ret; // 错误
        }
        if ((HAL_GetTick() - start_tick) > timeout) break;
    }
    return recv_len;
}
```

## 3. 步骤二：MQTT 核心应用实现

在工程中创建 `BSP/mqtt_app.c` (或在 `main.c` 中编写) 实现连接逻辑。

### 3.1 定义连接参数
```c
#define MQTT_SOCKET     0
#define MQTT_BUF_SIZE   2048

uint8_t mqtt_tx_buf[MQTT_BUF_SIZE];
uint8_t mqtt_rx_buf[MQTT_BUF_SIZE];

Network n;
MQTTClient c;

// Broker 配置
uint8_t target_ip[4] = {116, 62, 226, 174}; // broker.emqx.io
uint16_t target_port = 1883;

// Topic 定义
char* sub_topic = "w5500/control";
char* pub_topic = "w5500/status";
```

### 3.2 消息回调函数 (Data 回传关键)
当 W5500 收到消息时，会触发此回调。我们将收到的内容原样发回给 MQTTX。

```c
void messageArrived(MessageData* md) {
    MQTTMessage* message = md->message;
    
    // 打印收到的消息
    printf("Topic: %.*s, Payload: %.*s\r\n", 
           md->topicName->lenstring.len, md->topicName->lenstring.data,
           (int)message->payloadlen, (char*)message->payload);

    // 数据回传 (Echo)
    MQTTMessage pub_msg;
    pub_msg.qos = QOS0;
    pub_msg.payload = message->payload;
    pub_msg.payloadlen = message->payloadlen;
    
    MQTTPublish(&c, pub_topic, &pub_msg);
}
```

### 3.3 初始化与连接流程
```c
void mqtt_init(void) {
    NewNetwork(&n, MQTT_SOCKET);
    ConnectNetwork(&n, target_ip, target_port);
    
    MQTTClientInit(&c, &n, 1000, mqtt_tx_buf, MQTT_BUF_SIZE, mqtt_rx_buf, MQTT_BUF_SIZE);
    
    MQTTPacket_connectData data = MQTTPacket_connectData_initializer;
    data.willFlag = 0;
    data.MQTTVersion = 3;
    data.clientID.cstring = "W5500_STM32_Test";
    data.keepAliveInterval = 60;
    data.cleansession = 1;

    if (MQTTConnect(&c, &data) == SUCCESS) {
        printf("MQTT Connected!\r\n");
        MQTTSubscribe(&c, sub_topic, QOS0, messageArrived);
    }
}
```

## 4. 步骤三：主循环调用

MQTT 需要在 `main` 循环中持续调用 `MQTTYield` 来维持心跳和处理收包。

```c
int main(void) {
    // ... W5500 硬件初始化 ...
    w5500_init();
    mqtt_init();
    
    while (1) {
        MQTTYield(&c, 100); // 100ms 处理周期
    }
}
```

## 5. 步骤四：MQTTX 测试步骤

### 5.1 配置 MQTTX 连接
1. 打开 MQTTX，点击左侧 `+` 新建连接。
2. **Name**: W5500_Test
3. **Host**: `mqtt://broker.emqx.io` (或使用你配置的 IP)
4. **Port**: 1883
5. 点击右上角 **Connect**。

### 5.2 订阅状态主题
为了看到 W5500 回传的数据，我们需要在 MQTTX 中订阅 `w5500/status`：
1. 点击 **New Subscription**。
2. **Topic**: `w5500/status`
3. 点击 **Confirm**。

### 5.3 发送控制指令
1. 在右下角发送框，设置 Topic 为 `w5500/control`。
2. Payload 输入：`{"msg": "Hello W5500"}`。
3. 点击发送按钮。

### 5.4 验证回传 (Echo)
- **现象**：在 MQTTX 的消息面板中，你会立即收到一条来自 `w5500/status` 的消息，内容与你发送的完全一致。
- **串口监控**：STM32 串口应打印 `Topic: w5500/control, Payload: {"msg": "Hello W5500"}`。

## 6. 排障手册 (Troubleshooting)

| 现象 | 可能原因 | 解决方法 |
| :--- | :--- | :--- |
| **MQTTConnect 失败** | W5500 无法访问外网 | 检查网关 (GW) 配置，确保能 Ping 通外网 IP。 |
| **MQTTX 连接不上** | 网络防火墙或代理 | 尝试关闭本地防火墙，或使用手机热点测试。 |
| **频繁掉线** | MilliTimer 未正常工作 | 检查 `SysTick_Handler` 是否正确调用了 `MilliTimer_Handler`。 |
| **收不到回传消息** | Socket 冲突 | 确保 MQTT 使用的 Socket 编号 (如 0) 未被其他应用 (如 Loopback) 占用。 |

---

## 7. 总结
通过 MQTT 协议，W5500 实现了从局域网到互联网的跨越。关键点在于 `MQTTYield` 的持续调用以及对 `messageArrived` 回调的正确处理。
