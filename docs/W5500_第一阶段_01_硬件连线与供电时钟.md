# W5500 第一阶段 Step 1：硬件连线与供电时钟（最小必需）

目标：让 W5500 在“物理层”满足工作条件。后续所有软件步骤都建立在“供电稳、时钟在、PHY 能 Link”的前提上。

## 1. 供电（必须先确认）

- W5500 芯片供电为 3.3V（模块通常也要求 3.3V，少数带稳压/电平转换的模块例外）
- 供电不稳的典型症状：
  - `VERSIONR` 读到 0x00/0xFF/随机
  - Link 灯乱闪、插网线时不亮
  - 一开始能通，过一会儿死机/断链

建议：
- 3.3V 电源要有足够电流余量
- W5500 旁边去耦电容齐全（模块通常已做，但自制板一定要检查）

## 2. 时钟（25MHz）

W5500 需要 25MHz 时钟。常见模块已自带 25MHz 晶振/有源晶振。

检查方法（不拆板也能做）：
- 如果你的串口自检能稳定读到 `VERSIONR=0x04`，一般说明芯片内部时钟链路是 OK 的
- 如果 `VERSIONR` 偶发异常，优先怀疑供电/时钟/焊接

## 4. RJ45 与 PHY Link（最硬的硬指标）

### 4.1 你应该看到的现象

- 网线插上后，RJ45 的 LINK 灯应常亮（大多数模块如此）
- ACT 灯会随数据收发闪烁

### 4.2 代码侧的 Link 证据

你现在能在串口打印中看到 `PHYLINK=1`，这是“物理链路已建立”的软件证据：
- [bsp_w5500.c](file:///i:/AI/w5500/BSP/bsp_w5500.c#L60-L77)

如果 `PHYLINK=0`：
- 先检查网线是否插到正确端口（路由器 LAN/交换机）
- 换一根网线/换一个 LAN 口
- 检查变压器/RJ45 焊接或模块硬件

## 5. 复位与中断（可选但要知道）

### 5.1 RST（复位）

本工程未通过 GPIO 控制 W5500 的 RST 引脚（看不到对应 GPIO）。这意味着：
- 你依赖模块自身上电复位电路
- 如果模块复位不可靠，可能出现“偶发启动失败”

如果你后续遇到“偶发 VERSIONR 不对、偶发网络不起来”，建议加一个 RST 引脚由 MCU 控制（后续阶段可扩展）。

### 5.2 INT（中断）

本工程当前未使用 INT 引脚。W5500 即使不用 INT，也能通过轮询方式实现 TCP/UDP 通信，只是实时性与功耗策略不同。

## 6. Step 1 的验收（你做完要得到什么）

- 插网线后 LINK 灯常亮（或至少 PHYLINK=1）
- 串口打印：`VERSIONR=0x04`
- 串口打印：`PHYLINK=1`

如果这三项同时满足，才能进入 Step 2（STM32 SPI/GPIO 配置）。
