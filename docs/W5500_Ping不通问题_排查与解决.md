# W5500 Ping 不通问题：排查与解决（本次实战复盘）

本文档记录一次典型的 W5500 联网故障从“完全 ping 不通”到“稳定 ping 通”的完整排查过程与解决方案。内容按“现象 → 证据 → 缩小范围 → 根因 → 修复 → 验收”组织，适合后续复用。

## 1. 背景与目标

目标网络参数（板子静态 IP）：
- IP：`192.168.227.88`
- 子网掩码：`255.255.255.0`
- 网关：`192.168.227.162`

目标现象：
- PC 能 `ping 192.168.227.88` 成功，并能在 ARP/邻居表里看到 W5500 的 MAC。

## 2. 初始现象（问题描述）

PC 上 `ping 192.168.227.88` 失败，典型输出包括：
- `请求超时`
- `来自 192.168.227.1 的回复: 无法访问目标主机。`

进一步观察发现：
- PC 可以 ping 通网关 `192.168.227.162`
- 但对 `192.168.227.88` 的 ARP/邻居解析失败

## 3. 核心排查思路（先分层）

W5500 这类问题最有效的分层路径是：

1）物理层：网线/口/PHY 链路是否 OK  
2）链路层：ARP 是否能互相学习 MAC  
3）网络层：ICMP（ping）是否被屏蔽/路由是否正确  
4）应用层：TCP/UDP 服务再往上做

把“ping 不通”拆成两种关键状态：
- **ARP 都不通**：问题在物理链路/二层广播域/对端根本没工作
- **ARP 通但 ping 不通**：问题在 ICMP（PingBlock）或回包路径

## 4. PC 侧证据链与判读

### 4.1 先确认网关可达

```powershell
ping 192.168.227.162
```

如果网关可达，说明：
- PC 的 WLAN/以太网至少有一条链路在 `192.168.227.0/24`
- 本机到路由器路径没问题

### 4.2 看 ARP/邻居表（决定分支）

先触发一次访问：

```powershell
ping 192.168.227.88 -n 1
```

再看邻居表（无需管理员权限）：

```powershell
powershell -NoProfile -Command "Get-NetNeighbor -AddressFamily IPv4 | ? IPAddress -eq '192.168.227.88' | fl *"
```

本次故障中观测到：
- `State : Unreachable`
- `LinkLayerAddress : 00-00-00-00-00-00`

判读结论：
- **ARP 未解析到 MAC**（等价于“二层没通”），此时不要纠结 PingBlock/ICMP。

### 4.3 ipconfig 定位“走错网卡/没拿到 DHCP”

```powershell
ipconfig
```

本次关键输出：
- WLAN：`192.168.227.1/24`，网关 `192.168.227.162`
- 以太网 3：`169.254.x.x/16`，无网关

判读结论：
- `169.254.x.x` 是 APIPA，表示 **以太网物理连上了，但 DHCP 没拿到地址**
- 此时 PC 对 `192.168.227.88` 的访问通常仍在 WLAN 上发起 ARP（除非手动指定源地址/路由），导致“找不到对端”

## 5. 板子侧证据链（确认 W5500 是否真的工作）

仅靠 PC 侧判断不够，需要板子侧给出“芯片是否在工作”的硬证据。最有效的是打印：
- `VERSIONR`（必须为 `0x04`）
- `PHYLINK`（必须为 1/ON）
- 当前 `MAC/IP/SN/GW/DNS/DHCP`（确认写入成功）

本次加入的自检输出（串口）示例：

```
W5500 VERSIONR=0x04 MR=0x00 PHYLINK=1
MAC=00:08:DC:11:11:11
IP=192.168.227.88 SN=255.255.255.0 GW=192.168.227.162 DNS=8.8.8.8 DHCP=1
```

判读结论：
- SPI 正常（否则 VERSIONR 很容易变成 0x00/0xFF/随机）
- PHY 链路正常（说明网线/口至少连上）
- 网络参数写入成功（W5500 处于静态网络参数状态）

因此“PC 侧 ARP 不通”不再是固件/硬件底层问题，而是网络拓扑/网卡选择问题。

## 6. 根因定位（本次的真正原因）

### 6.1 代码层问题（早期）

早期工程里只定义了网络参数函数，但没有在启动阶段完成 W5500 的 ioLibrary 回调注册与初始化调用，导致 W5500 无法正常响应网络。

修复点（本次已完成）：
- 注册回调：CS/SPI/临界区
- 调用 `wizchip_init()` 配置 socket buffer
- 调用 `wizchip_setnetinfo()` 写入静态网络参数
- 在 `main()` 初始化阶段调用 `w5500_init()` 并打印 `w5500_dump()`

### 6.2 网络拓扑/网卡选择问题（最终导致 ping 不通）

关键事实：
- PC 的 `192.168.227.1` 在 **WLAN**
- PC 的 **以太网 3** 处于 `169.254.x.x`（没有加入 `192.168.227.0/24`）
- 对 `192.168.227.88` 的 ARP 在 WLAN 上发起，无法解析到 MAC，导致 `Unreachable`

最终通过让 PC 正确走“以太网 3”同网段访问 W5500 后，ping 立即恢复正常。

## 7. 解决步骤（可复用操作清单）

根据你的物理连接方式，选择其中一种方案：

### 方案 A：PC 直连 W5500（最常见于调试）

1）打开网卡面板：
- `Win + R` → 输入 `ncpa.cpl`

2）把“以太网 3”设置为静态 IP（与 W5500 同网段）：
- IP：`192.168.227.10`
- Mask：`255.255.255.0`
- 网关：留空（直连不需要）

3）验证（可强制指定源地址，避免走错网卡）：

```powershell
ping -S 192.168.227.10 192.168.227.88
arp -a | findstr 192.168.227.88
```

### 方案 B：PC 与 W5500 都接到路由器 LAN（适合长期使用）

1）确认两根网线都插在路由器 LAN 口（不是 WAN/Internet）  
2）PC 的以太网使用 DHCP 自动获取  
3）`ipconfig` 验证以太网获得 `192.168.227.x` 且网关为 `192.168.227.162`  
4）`ping 192.168.227.88` 验收

如果 Wi-Fi 能上网但访问不到有线设备，额外检查：
- 路由器是否开启“无线客户端隔离/AP 隔离”

## 8. 验收标准（如何确认问题真正解决）

- `ping 192.168.227.88`：0% 丢包
- `arp -a` 或 `Get-NetNeighbor`：能看到 `192.168.227.88` 对应的真实 MAC（不再是 00-00-00-00-00-00）
- 串口自检：`VERSIONR=0x04`，`PHYLINK=1`，网络参数正确

## 9. 一页纸经验总结（下次直接照抄）

- **先看 ARP，再谈 ping**：ARP 不通，ICMP 再怎么调都没用  
- `169.254.x.x` = DHCP 没拿到地址：通常意味着“你以太网没加入目标网段”  
- 多网卡共存时，`ping` 可能走错网卡：用 `ping -S <source-ip>` 强制走指定接口  
- W5500 bring-up 先做两件事：`VERSIONR=0x04` 与 `PHYLINK=1`
