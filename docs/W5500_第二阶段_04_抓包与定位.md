# W5500 第二阶段 Step 4：抓包与定位（Wireshark + Socket 状态）

目标：当 UDP/TCP 不通时，你能用“抓包 + W5500 socket 状态”快速定位是哪一层的问题，而不是盲改代码。

## 1. 抓包基本操作

抓包网卡要选对：
- 你 PC 实际与板子通信的那张网卡（以太网/无线）

常用过滤器：
- ARP：`arp`
- ICMP：`icmp`
- UDP 指定端口：`udp.port == 5000`
- TCP 指定端口：`tcp.port == 5001`

## 2. 先看 L2/L3：ARP 与 ping 是否正常

### 2.1 ARP

- 只看到 PC 发 ARP Request，没有 ARP Reply：二层不通（网段/隔离/走错网卡/板子没响应）
- 能看到 ARP Reply：二层 OK

### 2.2 ICMP

- ARP OK 但 ping 不通：再检查 PingBlock（MR.PB）或路由回包路径

你当前第一阶段已经验证 MR=0x00，正常情况下不会屏蔽 ping。

## 3. UDP 抓包判读

你应该看到：
- PC → 板子：UDP request
- 板子 → PC：UDP reply

如果只有 request 没有 reply：
- 板子没有收到（可能 UDP 端口不对/走错网卡/板子 socket 未打开）
- 或板子收到了但没回（状态机/发送失败）

## 4. TCP 抓包判读（最重要）

### 4.1 连接建立（3 次握手）

正常握手：
- SYN（发起端 → 目标端）
- SYN-ACK（目标端 → 发起端）
- ACK（发起端 → 目标端）

常见异常：
- 只有 SYN，没有 SYN-ACK：目标端没监听/防火墙/走错网卡/目标端口不通
- SYN 有，SYN-ACK 有，但后续一直重传：中间链路或状态机异常

### 4.2 数据收发

你应该看到：
- 发数据的那一方发送 PSH/ACK（或 ACK）
- 另一方 ACK 并回数据（如果是 echo）

### 4.3 断开

正常断开通常会看到 FIN/ACK 交换。

如果你看到对端发 FIN 后，板子不处理：
- 常见是板子没处理 `SOCK_CLOSE_WAIT`，导致 socket 卡住

## 5. 配合 W5500 Socket 寄存器定位（板子侧）

你要在串口里打印以下信息（最常用）：
- `getSn_SR(sn)`：socket 状态（TCP/UDP/closed/established…）
- `getSn_RX_RSR(sn)`：接收缓冲区长度（有数据才 recv）
- `getSn_TX_FSR(sn)`：发送缓冲区空闲长度（大数据时很重要）
- `getSn_IR(sn)`：连接/断开等中断事件（如 `Sn_IR_CON`）

这些 API/宏在官方 loopback 里都有用法范例：
- [loopback.c](file:///i:/AI/w5500/ioLibrary_Driver/Application/loopback/loopback.c#L17-L220)

## 6. 最实用的定位组合（背下来）

- “PC 连不上 TCP 端口”  
  先抓包看 SYN 是否有回应 → 再看板子 `getSn_SR()` 是否在 LISTEN（Server）或 INIT/ESTABLISHED（Client）

- “UDP 只有发出没有回包”  
  抓包确认 request 到达板子 → 看板子是否 `SOCK_UDP` → 看 `recvfrom()` 返回值

- “断线后无法重连”  
  抓包看是否在不断重传 SYN/FIN → 板子侧确认是否处理 `SOCK_CLOSE_WAIT` 并 close/reopen

## 7. Step 4 验收标准

- 你能用抓包明确判断：包到没到、是谁没回、是握手阶段还是数据阶段
- 你能用 `getSn_SR/getSn_RX_RSR` 的打印把问题定位到 socket 状态机分支
